# وایرو روی اینترنت ملی و قطعی اینترنت بین‌الملل

## هدف محصول

هدف، «نمایش نسخهٔ آفلاین» نیست. هدف این است که کاربر هنگام محدود یا قطع‌شدن مسیر اینترنت بین‌الملل، تا وقتی شبکهٔ داخلی در دسترس است، همچنان به سرورهای وایرو وصل شود و پروفایل، چت، اکسپلور و محتوای مجاز را به‌صورت آنلاین ببیند و تغییر دهد.

این هدف فقط با تغییر رابط کاربری یا افزودن VPN محقق نمی‌شود؛ سرویس‌های موردنیاز باید از همان شبکه قابل دسترسی باشند.

## وضعیت فعلی مخزن

- کلاینت از `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY` برای اتصال به Supabase استفاده می‌کند.
- نشانی فعلی پروژه Supabase روی دامنه `supabase.co` است؛ دسترسی به آن در زمان محدودیت اینترنت ملی تضمین‌شده نیست.
- برنامه در حال حاضر کلاینت بومی VPN یا سرویس Android `VpnService` ندارد؛ لینک Subscription به‌تنهایی VPN را در برنامه فعال نمی‌کند.
- GitHub Pages فقط فایل‌های وب را میزبانی می‌کند و جایگزین API، دیتابیس، ذخیره‌سازی رسانه یا سرویس چت نیست.
- بخش‌هایی از چت و امکانات اجتماعی هنوز نیازمند تکمیل اتصال آنلاین و آزمایش هستند.

## معماری موردنیاز برای دسترسی آنلاین از شبکه داخلی

1. **زیرساخت داخلی:** یک سرور/میزبانی در شبکه‌ای که کاربران هدف هنگام محدودیت اینترنت بین‌الملل به آن دسترسی دارند، به‌همراه دامنه و TLS معتبر لازم است. دسترسی از اپراتورها و شبکه‌های مختلف باید واقعاً آزمایش شود.
2. **Backend در دسترس داخلی:** نمونهٔ self-hosted از Supabase یا backend سازگار باید شامل PostgreSQL، Auth، REST API، Realtime، Storage و Edge Functions موردنیاز وایرو باشد. همهٔ این سرویس‌ها و وابستگی‌هایشان باید از مسیر داخلی قابل دسترسی باشند.
3. **مهاجرت داده:** جدول‌ها، سیاست‌های RLS، کاربران، فایل‌ها، توابع و تنظیمات Auth باید با طرح مهاجرت و آزمایش انتقال شوند. تغییر آدرس URL به‌تنهایی داده‌ها یا حساب‌های موجود را منتقل نمی‌کند.
4. **وب‌اپ و فایل‌های رسانه:** برای دسترسی در زمان قطع بین‌الملل، فایل‌های وب، DNS، تصاویر، ویدئوها و فایل‌های ضمیمه نیز باید از دامنه/ذخیره‌سازی در دسترس داخلی سرو شوند؛ GitHub Pages یا CDN خارجی به‌تنهایی کافی نیست.
5. **پیکربندی build:** پس از آماده‌شدن backend داخلی، مقدار GitHub Actions secret به‌نام `VITE_SUPABASE_URL` باید آدرس API داخلی و `VITE_SUPABASE_PUBLISHABLE_KEY` کلید عمومی همان پروژه باشد؛ سپس APK و وب‌اپ باید دوباره build شوند. کلید `service_role` هرگز نباید وارد اپ یا secrets قابل دسترس فرانت‌اند شود.
6. **آزمایش واقعی:** با قطع دسترسی بین‌الملل و روشن‌بودن فقط مسیر داخلی، ورود، خواندن/ویرایش پروفایل، پیام‌رسانی بین دو دستگاه، آپلود رسانه و بازیابی اتصال باید آزمایش شوند. تا این آزمون انجام نشود، پشتیبانی از اینترنت ملی تأییدشده محسوب نمی‌شود.

## VPN و به‌روزرسانی Subscription

لینک Subscription نباید داخل مخزن عمومی یا رشته‌های رابط کاربری قرار گیرد. برای اجرای واقعی نیاز است:

- یک کلاینت Android بومی با پشتیبانی از پروتکل واقعی سرویس تهیه/پیاده‌سازی شود؛ برنامهٔ فعلی فقط React/Capacitor است و چنین موتور VPNای در آن وجود ندارد.
- کلاینت باید اجازهٔ سیستمی VPN را از کاربر بگیرد.
- لینک Subscription در یک بخش امن سمت سرور نگهداری شود، نه در GitHub عمومی. سرور باید آن را با کنترل دسترسی دریافت کند.
- در شروع اتصال و سپس با فاصلهٔ زمانی محدود، Subscription دوباره دریافت شود؛ پاسخ اعتبارسنجی شود و فقط در صورت معتبر بودن، آخرین پیکربندی سالم جایگزین شود.
- در خطای شبکه یا پاسخ نامعتبر، پیکربندی سالم قبلی حفظ شود، تلاش مجدد با فاصلهٔ افزایشی انجام شود و حلقهٔ اتصال/قطع بی‌نهایت ایجاد نشود.
- برای محافظت از لینک و سهمیه، endpoint دریافت Subscription باید احراز هویت، محدودسازی درخواست و ثبت خطا داشته باشد. با این حال هر پیکربندی‌ای که به دستگاه داده می‌شود ممکن است توسط کاربر فنی استخراج شود؛ مخفی‌ماندن کامل آن از دستگاه ممکن نیست.

VPN فقط زمانی می‌تواند مسیر بین‌الملل را برگرداند که سرور VPN و مسیر رسیدن به آن هنوز از شبکهٔ کاربر قابل دسترسی باشد. VPN نمی‌تواند قطع کامل تمام مسیرها به سرور خود را برطرف کند.

## سرویس‌هایی که وابستگی خارجی دارند

- **چت و پروفایل:** می‌توانند آنلاین کار کنند، اگر backend و فایل‌ها در شبکهٔ داخلی قابل دسترسی باشند.
- **هوش مصنوعی:** وابسته به API خارجی در زمان قطع کار نخواهد کرد؛ برای ادامهٔ پاسخ‌دهی، مدل محلی یا سرویس هوش مصنوعی قابل دسترس داخلی لازم است.
- **موسیقی:** Spotify و کاتالوگ‌های خارجی ممکن است در دسترس نباشند؛ باید منبع دارای مجوز و قابل دسترس داخلی فراهم شود.
- **اعلان‌ها:** سرویس‌های اعلان خارجی ممکن است در دسترس نباشند؛ باید مسیر اعلان جایگزین و قابل دسترس داخلی طراحی شود.

## پیش‌نیاز عملی برای استقرار

این مخزن به‌تنهایی نمی‌تواند سرور داخلی، دامنه، گواهی TLS یا حساب میزبانی را ایجاد کند. برای تکمیل استقرار باید دسترسی مدیریتی به یک میزبان سازگار در شبکهٔ هدف و تصمیم دربارهٔ دامنه/ارائه‌دهنده فراهم شود. هیچ رمز، کلید خصوصی یا لینک Subscription را در issue، commit یا فایل عمومی قرار ندهید.
